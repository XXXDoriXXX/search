# 06. Варіанти та trade-off

По кожному шару три варіанти. Рекомендація позначена **(R)**.

## 1. Discovery: звідки беремо ліди

| | A. Search-API-first | B. Own index | C. Hybrid **(R)** |
|---|---|---|---|
| Суть | SerpAPI/Bing/Brave/Exa/Tavily + власний fetch | Власний краулер + Common Crawl + фіди | A + вертикальні конектори + архіви + PKG як кеш |
| Time-to-MVP | 2-3 тижні | місяці | 4-6 тижнів |
| T3 (рідкісні) | слабко: індекси не бачать PDF-каталоги, архіви | найкраще, але дорого | сильно за рахунок Wayback/CC/дистриб'юторів |
| Вартість/запит | $0.05-0.20 | низька на запит, висока інфра | $0.05-0.15, падає з ростом PKG |
| Ризики | залежність від API-квот | інженерна складність, підтримка краулера | складність конекторів (мітигується plugin-інтерфейсом) |

C дає найкращий баланс і природній шлях еволюції до B: конектори + PKG поступово стають власним індексом продуктів.

## 2. Екстракція

| | A. Pure LLM | B. Rules-only | C. Layered **(R)** |
|---|---|---|---|
| Суть | Уся сторінка → LLM structured output | JSON-LD/microdata/table parsers | structured → tables → PDF → LLM на main-content, grounding check |
| Точність | Висока на чистих сторінках, галюцинації на шумних | Дуже висока там, де є розмітка, нуль там, де немає | Висока + захист grounding-check |
| Вартість | Висока (токени) | Мінімальна | Середня: LLM тільки де правила не дали результату |
| Покриття | Широке | Вузьке | Широке |

## 3. Вирішення конфліктів

| | A. Majority vote | B. LLM-judge | C. Truth discovery + constraints + judge **(R)** |
|---|---|---|---|
| Суть | Більшість перемагає | LLM бачить усі кандидати і вибирає | Ітеративні ваги (CRH), незалежність, ledger, hard constraints, judge лише при conflict |
| Слабкі місця | Копії створюють фальшиву більшість | Непояснюваність, дрейф, дорого | Складніше в реалізації, потребує ledger |
| Пояснюваність | Проста | Текстова | Повна: голоси, ваги, margin, constraints |
| Precision | Низька-середня | Середня | Найвища серед варіантів |

Альтернатива для розгляду пізніше: повний Bayesian truth discovery (Latent Truth Model) з навчанням на golden dataset. Дає кращу калібрування, але потребує даних; CRH-стиль стартує без навчання.

## 4. Entity matching

| | A. String similarity | B. Identifier-only | C. Identifier + variant axes + attribute consistency **(R)** |
|---|---|---|---|
| Плюси | Простий | Точний | Точний і працює без ID |
| Мінуси | Сусідні моделі проходять | Без ID нічого не матчиться (T3) | Потребує онтології варіантних осей |

## 5. Оркестрація

| | A. asyncio + Redis-черга | B. Temporal **(R для prod)** | C. Prefect/Airflow |
|---|---|---|---|
| Durable/Retry | вручну | вбудовано | частково |
| Видимість DAG | своя | UI з коробки | UI |
| Складність | низька | середня | середня |
| Fit | MVP | prod, батчі на мільйони товарів | ETL-стиль, гірше для sub-minute latency |

Рекомендація: MVP на asyncio з чистими межами задач, які потім стають Temporal activities без переписування логіки.

## 6. Сховище знань

| | A. Тільки кеш (Redis) | B. Postgres + pgvector **(R)** | C. Графова БД (Neo4j) |
|---|---|---|---|
| Aliases / embeddings | ні | так | потребує окремого vector store |
| Relations (variants, successors) | ні | так, реляційно | природньо |
| Ops | просто | просто, одна БД | ще одна система |

Графова БД має сенс, коли relations стануть основним use case (порівняння, сумісність). Для PTE це не перша версія.

## 7. LLM

| | A. Один великий LLM на все | B. Малий локальний на все | C. Каскад **(R)** |
|---|---|---|---|
| Суть | Claude для класифікації, екстракції, арбітражу | Локальна модель | Локальна/мала модель для класифікації і дешевої екстракції, велика для складних сторінок і арбітражу |
| Вартість | висока | низька | середня |
| Точність | найвища | нижча на складних PDF | висока там, де важливо |

## 8. Build vs Buy для окремих джерел

## 9. Що обрати, якщо бюджет обмежений

Мінімально життєздатний "правильний" варіант: C-discovery без Common Crawl, C-екстракція без vision, C-truth без LLM-judge (conflict залишається conflict), asyncio-оркестрація, Postgres. Цього достатньо для AC-C1..C6 на T1/T2; T3 і AC-R3 додаються фазою 3 (док 08).
