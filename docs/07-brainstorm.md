# 07. Brainstorm

Оцінка: **Impact** (1-5) / **Effort** (1-5). Ідеї з високим impact і низьким effort йдуть у roadmap першими.

## A. Ідентифікація та розрізнення варіантів

| Ідея | I/E | Коментар |
|---|---|---|
| **Spec fingerprint.** Вектор з 5-8 найдискримінативніших атрибутів категорії; сторінка, чий fingerprint суперечить якорю, знижується в entity_match ще до голосування | 5/2 | Ловить "сусідні моделі" без LLM |
| **Negative evidence.** Явно шукати сторінки сусідніх моделей (`GSR 12V-35` без FC) і використовувати їх як "анти-докази": значення, що збігаються з сусідом, але не з tier A, підозрілі | 4/2 | Дешева й дуже ефективна проти змішування |
| **Visual identity check.** CLIP-embedding зображень з tier A vs зображень з магазину: якщо не схожі, сторінка про інший товар/варіант | 3/3 | Добре для кольору/комплектації |
| **Barcode from images.** zbar по фото упаковки в листингах → GTIN | 3/2 | Часто єдиний GTIN для T3 |
| **Wikidata як ID-hub.** Записувати знайдені відповідності `MPN ↔ GTIN ↔ ASIN ↔ Icecat id` у PKG і, за бажанням, контриб'ютити у Wikidata | 3/2 | Мережевий ефект |
| **Rebrand map.** Таблиця ребрендингів і OEM-клонів (один завод, різні бренди) для розширення пошуку | 3/2 | Важливо для азійських товарів |

## C. Правдивість

| Ідея | I/E | Коментар |
|---|---|---|
| **Copy-chain detection** (MinHash + власники доменів) | 5/2 | Без цього всі голосування хибні |
| **Adversarial verifier agent.** Окремий LLM-агент, чия задача — спростувати кожне `verified`-поле, знайшовши суперечливе джерело | 4/3 | Запускати вибірково (дорогі поля, аудит) |
| **Cross-field physics.** Wh = V×Ah, щільність (вага/об'єм) у діапазоні матеріалу, роздільна здатність vs пропорції, потужність vs струм×напруга | 4/2 | Ловить одруківки виробників |
| **Revision-aware facts.** Спека може змінюватись між ревізіями (v1/v2, 2019/2021). Поле `revision` як варіантна вісь, докази з датою | 3/3 | Важливо для електроніки |
| **Calibrated confidence.** Ізотонічна регресія confidence → фактична точність по golden | 4/2 | Без цього confidence — декорація |
| **Source reliability per (domain, category, field)** | 5/2 | Магазин може бути точним по вазі й брехати по гарантії |
| **Self-consistency екстракції.** 2 прогони LLM з різним chunking; розбіжність → нижча confidence | 3/1 | Дешево |
| **Human-in-the-loop queue.** `conflict`-поля дорогих товарів у чергу на ручну перевірку; результат → ledger + golden | 4/2 | Замикає цикл навчання |

## F. Свідомо відкинуті ідеї

- **"Нехай LLM просто напише JSON з того, що знає."** Джерело галюцинацій; не проходить AC-C4.
- **Одна велика модель, що читає 50 сторінок за раз.** Дорого, змішує варіанти, нема grounding.
- **Обхід CAPTCHA / anti-bot.** Юридичний ризик і крихкість; замість цього API, партнерства, архіви.
- **Fine-tuning екстрактора на старті.** Без golden dataset нема на чому; спочатку layered extraction + ledger.
